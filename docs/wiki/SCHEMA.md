# LLM 위키 스키마

## 목적

이 위키는 Subway Push 프로젝트의 장기 기억이다. LLM 에이전트가 코드를 변경하기 전에 프로젝트 목표, 현재 상태, 아키텍처, 결정 사항, 기능, 실행 절차, 반복 실수를 빠르게 이해하도록 돕는다.

## 기준 정보

- `raw/`는 원본 자료와 과거 기록을 저장한다.
- `wiki/`는 LLM이 관리하는 요약 문서를 저장한다.
- `raw/`와 `wiki/`가 충돌하면 `raw/`를 우선 신뢰한다.
- 코드와 위키가 충돌하면 코드를 먼저 확인한 뒤 위키를 갱신한다.
- 기존 `../features/` 기록은 구현 이력의 근거 자료로 사용한다.

## 디렉터리 규칙

- `raw/` 아래 파일은 생성 후 수정하지 않는다.
- 새 위키 파일을 만들기 전에 기존 `wiki/` 파일을 먼저 갱신한다.
- 위키 문서는 짧고 명확하게 유지한다.
- 원본 내용을 길게 복사하지 않는다.
- 중요한 주장에는 근거 경로를 남긴다.
- 불확실한 내용은 `미확인`으로 표시한다.
- 오래된 내용은 조용히 삭제하지 말고 `오래된 내용` 섹션으로 옮긴다.

## raw 디렉터리

- `raw/notes/`는 아이디어, 요구사항, 설계 메모를 저장한다.
- `raw/issues/`는 버그, TODO, 이슈 기록을 저장한다.
- `raw/references/`는 외부 문서와 참고 자료를 저장한다.
- `raw/logs/`는 작업 로그, 에러 로그, 실패한 시도를 저장한다.

## wiki 디렉터리

- `wiki/index.md`는 가장 먼저 읽는 파일이다.
- `wiki/overview.md`는 프로젝트 요약과 현재 상태를 설명한다.
- `wiki/architecture.md`는 시스템 구조와 책임 경계를 설명한다.
- `wiki/features.md`는 기능별 동작과 구현 상태를 추적한다.
- `wiki/decisions.md`는 중요한 결정과 이유를 기록한다.
- `wiki/runbook.md`는 세팅, 테스트, 마이그레이션, 운영 명령을 기록한다.
- `wiki/mistakes.md`는 반복 실수와 올바른 해결책을 기록한다.

## 갱신 흐름

새 원본 자료가 추가되면 아래 순서로 처리한다.

1. 관련 `raw/` 파일을 읽는다.
2. 영향을 받는 `wiki/` 파일을 읽는다.
3. 새 파일을 만들기 전에 기존 위키 파일을 갱신한다.
4. 중요한 주장에는 근거 경로를 추가한다.
5. 문서 구조가 바뀌면 `wiki/index.md`를 갱신한다.
6. 반복되는 에러나 잘못된 시도는 `wiki/mistakes.md`에 기록한다.

## 코딩 전 확인 순서

코드 변경 전에는 아래 파일을 읽는다.

1. `wiki/index.md`
2. `wiki/overview.md`
3. `wiki/architecture.md`
4. `wiki/features.md`
5. `wiki/decisions.md`
6. `wiki/mistakes.md`

세팅, 테스트, 마이그레이션, 배포, 운영 명령이 필요하면 `wiki/runbook.md`도 읽는다.

## 출처 규칙

- 중요한 주장은 근거 경로를 포함해야 한다.
- 막연한 설명보다 저장소 파일 경로를 우선 사용한다.
- 근거가 약하면 `미확인`으로 표시한다.
- 근거가 충돌하면 `충돌` 섹션을 추가한다.
- 요구사항, 결정, 아키텍처를 임의로 만들지 않는다.

## 문체 규칙

- 간결하게 쓴다.
- 의견보다 사실을 우선한다.
- 모든 함수를 나열하지 말고 책임 경계를 설명한다.
- 이후 코딩 작업에 바로 도움이 되는 문서로 유지한다.
