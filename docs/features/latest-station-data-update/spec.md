# Spec. Latest Station Data Update

> 한 줄 요약. 서울 열린데이터광장에서 최신 지하철역 기준 데이터를 가져와 API와 모바일 정적 데이터를 같은 원본에서 생성한다.

## 배경

현재 역 데이터는 API의 `apps/api/src/stations/stations.data.ts`와 모바일의 `apps/mobile/lib/data/stations.dart`에 각각 정적으로 존재한다. 두 파일이 별도로 관리되면 신규역, 역명 변경, 노선 변경을 놓치거나 API와 모바일의 역 데이터가 서로 달라질 수 있다.

이 기능은 서울 열린데이터광장의 `서울교통공사_노선별 지하철역 정보`를 기준으로 최신 역 목록을 가져와 단일 JSON 원본으로 정규화한다. 그 뒤 같은 JSON에서 TypeScript와 Dart 정적 데이터 파일을 생성해 API와 모바일이 같은 역 기준 데이터를 사용하게 한다.

역 목록은 기준 정보이므로 수동 실행 스크립트로 갱신하고, 생성 결과는 사람이 diff로 검토한 뒤 커밋한다.

## 기능 목록

### 서울 열린데이터광장 역 데이터 가져오기

루트 `.env`의 `SEOUL_OPEN_DATA_API_KEY`를 사용해 서울 열린데이터광장 API에서 노선별 지하철역 정보를 가져온다.

**동작 방식**

- 루트에서 `npm run update:stations`를 실행한다.
- 스크립트는 `.env`의 `SEOUL_OPEN_DATA_API_KEY`를 읽는다.
- 서울 열린데이터광장의 `서울교통공사_노선별 지하철역 정보`만 데이터 출처로 사용한다.
- 한 번에 최대 1,000건 제한을 고려해 필요하면 page 또는 range 단위로 나누어 요청한다.

**포함 범위**

- 루트 실행 스크립트.
- `.env.example`의 `SEOUL_OPEN_DATA_API_KEY` 예시.
- API 응답 파싱과 기본 검증.

**제외 범위**

- TOPIS 직접 연동. 현재는 서울 열린데이터광장을 단일 출처로 둔다.
- 공공데이터포털 직접 연동. 현재는 메타데이터 참고용으로만 둔다.

### 단일 JSON 원본 생성

외부 응답을 프로젝트 내부에서 쓰기 쉬운 `data/stations.json`으로 정규화한다.

**동작 방식**

- 역명, 호선, 외부 역 코드, 전철역 코드, 다국어 역명 필드를 가능한 범위에서 보존한다.
- 프로젝트 UI에 필요한 description은 기존 데이터와 공공 데이터의 행정구 정보 부족을 고려해 별도 규칙으로 유지하거나 비워둔다.
- 같은 역명의 여러 호선을 하나의 station 항목으로 병합한다.
- line 목록은 안정적인 순서로 정렬한다.

**포함 범위**

- `data/stations.json`.
- 정규화 타입 정의.
- 중복 역 병합 규칙.

**제외 범위**

- 좌표 데이터 보강. 이 API에서 안정적으로 제공되지 않으면 별도 기능으로 분리한다.
- 역 상세 설명 자동 생성. 행정구나 환승역 설명은 기존 UI 표시 요구와 별도 검토가 필요하다.

### API와 모바일 정적 파일 생성

`data/stations.json`을 기준으로 API용 TypeScript 데이터와 모바일용 Dart 데이터를 생성한다.

**동작 방식**

- `apps/api/src/stations/stations.data.ts`를 생성한다.
- `apps/mobile/lib/data/stations.dart`를 생성한다.
- 생성 파일에는 첫 줄 한국어 헤더 주석을 유지한다.
- line color 데이터는 기존 값을 유지하되 생성 흐름에서 누락되지 않게 관리한다.

**포함 범위**

- TypeScript 데이터 생성.
- Dart 데이터 생성.
- 생성 결과를 검증하는 테스트 또는 스냅샷성 검증.

**제외 범위**

- Flutter package name 변경.
- API 응답 계약 변경.
- DB 기반 station 테이블 도입.

## 입출력

**입력**

- `SEOUL_OPEN_DATA_API_KEY`. 문자열. 루트 `.env`에 저장된 서울 열린데이터광장 인증키.
- 서울 열린데이터광장 API 응답. 역명, 호선명, 외부코드, 전철역코드, 다국어 역명 등을 포함하는 XML 또는 JSON 응답.

**출력**

- `data/stations.json`. 정규화된 단일 역 데이터 원본.
- `apps/api/src/stations/stations.data.ts`. API에서 사용하는 정적 station dataset.
- `apps/mobile/lib/data/stations.dart`. 모바일에서 사용하는 정적 station dataset.

## 제약 조건

- 데이터 출처는 서울 열린데이터광장으로 제한한다.
- 인증키는 repository에 커밋하지 않는다.
- 생성 파일은 사람이 읽을 수 있어야 한다.
- 같은 입력으로 실행하면 같은 출력이 나와야 한다.
- API와 모바일의 역명, 노선 목록은 같은 JSON 원본에서 파생되어야 한다.
- 기존 `GET /stations` API 계약과 모바일 station model은 유지한다.

## 예외 케이스

- `SEOUL_OPEN_DATA_API_KEY` 없음 → 스크립트가 명확한 오류 메시지와 함께 종료한다.
- API 호출 실패 → 생성 파일을 부분 갱신하지 않고 종료한다.
- 응답 형식 변경 → 파싱 오류를 표시하고 기존 파일을 덮어쓰지 않는다.
- 중복 역 병합 충돌 → 충돌 역 목록을 출력하고 실패 처리한다.
- 알 수 없는 노선 → JSON에는 보존하되 line color 누락 경고를 출력한다.

## 채택 근거

**핵심 이유**

- API와 모바일의 역 데이터를 같은 원본에서 생성해 데이터 불일치를 줄인다.

**보조 이유**

- 수동 정적 파일 편집보다 최신성 관리가 쉽다.
- 실행 시점과 반영 diff를 통제할 수 있어 운영 부담이 낮다.
- 사람이 diff를 검토할 수 있어 잘못된 공공 데이터 반영을 막기 쉽다.

**기각된 대안**

- 정적 파일을 계속 수동 수정한다. 두 플랫폼 데이터가 다시 어긋날 가능성이 크다.
- 서버 DB에 station 테이블을 먼저 도입한다. 현재 목적은 정적 기준 데이터 갱신이므로 범위가 커진다.
- TOPIS 또는 공공데이터포털을 직접 호출한다. 이번 기능은 서울 열린데이터광장을 단일 출처로 제한한다.

## 비기능 요건

**성능**

- 역 데이터 갱신 스크립트는 로컬 수동 실행 기준 30초 이내 완료를 목표로 한다.
- 생성된 API와 모바일 정적 데이터 조회 성능은 기존과 동일하게 메모리 정적 배열 기준을 유지한다.

**보안**

- 위협 모델. 인증키 유출과 외부 응답 변조 또는 형식 변경을 주요 위험으로 본다.
- 인증키는 `.env`에서 읽고 git tracked 파일에 기록하지 않는다.
- 스크립트는 외부 응답을 그대로 코드 문자열로 삽입하지 않고 JSON escape 또는 생성기 escape를 거친다.

**확장성**

- 역 수가 1,000건을 넘으면 서울 열린데이터광장 range 호출을 나누어 처리한다.
- 수도권 전체 확장이나 좌표 보강이 필요해지면 별도 feature로 분리한다.

## 용어 정의

- **기준 역 데이터.** 역명, 호선, 역 코드처럼 앱과 API가 공유하는 정적 역 정보.
- **단일 JSON 원본.** API와 모바일 생성 파일의 기준이 되는 `data/stations.json`.
- **생성 파일.** JSON 원본에서 만들어지는 `stations.data.ts`와 `stations.dart`.
- **서울 열린데이터광장 인증키.** 서울 열린데이터광장 Open API 호출에 사용하는 키.
