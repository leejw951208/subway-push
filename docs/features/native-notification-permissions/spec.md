# Spec. Native Notification Permissions

> 한 줄 요약. Android/iOS에서 로컬 알림을 표시할 수 있도록 권한과 플랫폼 설정을 추가한다.

## 배경

현재 앱은 알림 방식 옵션을 UI로 선택할 수 있지만 실제 OS 알림, 진동, 음성 동작은 구현되어 있지 않다. 도착 알림 앱으로 동작하려면 먼저 네이티브 알림 권한과 로컬 알림 채널이 준비되어야 한다.

이 기능은 실제 위치 기반 도착 판정보다 앞선 기반 작업이다. 테스트용 로컬 알림 trigger를 통해 플랫폼 설정이 올바르게 동작하는지 확인한다.

## 기능 목록

### 알림 권한 및 로컬 알림 기반

앱이 알림 권한을 요청하고, 테스트 알림을 표시할 수 있게 한다.

**동작 방식**

- 앱에서 현재 알림 권한 상태를 확인한다.
- 권한이 없으면 사용자에게 요청한다.
- Android notification channel을 생성한다.
- 개발/테스트용 trigger로 로컬 알림을 표시한다.

**포함 범위**

- 알림 권한 요청
- Android notification channel
- 로컬 알림 plugin 초기화
- 테스트용 알림 발송 경로
- 권한 거부 상태 UI

**제외 범위**

- 서버 푸시. FCM/APNs는 별도 기능이다.
- 실제 지하철 도착 판정. arrival engine에서 처리한다.
- 백그라운드 위치 추적. 플랫폼 정책 검토가 필요하다.

## 입출력

**입력**

- 권한 요청 사용자 액션.
- 테스트 알림 payload: title/body.

**출력**

- OS 알림 권한 상태.
- 표시된 로컬 알림.
- 권한 거부/허용 UI 상태.

## 제약 조건

- Android 13+ 알림 권한 정책을 고려해야 한다.
- iOS는 권한 요청과 foreground 표시 정책을 분리해야 한다.
- 권한 거부 시 앱이 크래시하면 안 된다.

## 예외 케이스

- 권한 거부 → 안내 UI 표시, 테스트 발송 비활성화.
- plugin 초기화 실패 → 에러 상태 기록, 앱 기본 UI 유지.
- 알림 채널 이미 존재 → 재사용.

## 채택 근거

**핵심 이유**

- 도착 알림 엔진이 있어도 OS 알림 기반이 없으면 사용자에게 알릴 수 없다.

**보조 이유**

- 플랫폼 설정 문제를 위치/도착 판정 로직과 분리해 검증할 수 있다.
- Android emulator/device에서 빠르게 확인 가능하다.

**기각된 대안**

- 도착 엔진과 동시에 구현. 실패 원인 분리가 어렵다.
- 서버 푸시부터 구현. 백엔드/인증/디바이스 토큰이 필요해 범위가 크다.

## 비기능 요건

**성능**

- 알림 plugin 초기화는 앱 시작 체감 성능을 크게 저하하지 않아야 한다.

**보안**

- 위협 모델. 권한은 사용자 명시 동의 후 사용한다.
- 알림 payload에 민감 정보를 넣지 않는다.

**확장성**

- 이후 서버 푸시가 추가되어도 로컬 알림 표시 계층을 재사용할 수 있어야 한다.

## 용어 정의

- **로컬 알림.** 서버 없이 기기 앱이 직접 예약/표시하는 OS 알림.
- **Notification channel.** Android에서 알림 카테고리/중요도를 정의하는 단위.
