# Spec. Station Alert Selection

> 한 줄 요약. 사용자가 위치 권한 없이 내릴 역을 직접 선택하고, 선택한 역 기준으로 하차 알림을 준비할 수 있게 한다.

## 배경

지하철 지하 구간에서는 GPS와 기기 위치가 불안정해 현재 위치 기반 자동 감지가 신뢰하기 어렵다. 사용자가 위치 권한을 거부하는 경우도 있으므로, 위치 권한을 전제로 한 알림 흐름은 초기 버전의 핵심 전략으로 적합하지 않다.

현재 앱은 역 검색과 알림 설정 UI를 이미 제공하고, 사용자는 특정 역에 대한 알림을 만들 수 있다. 이 기능은 그 방향을 명확히 하여 “사용자가 내릴 역을 직접 선택하는 방식”을 기본 UX로 삼는다. 위치 권한 확인은 제거하고, 선택한 역을 기준으로 알림 옵션과 향후 수동 탑승 모드 또는 실시간 열차 위치 연동으로 확장할 수 있는 구조를 정리한다.

이번 기능은 위치 기반 자동 추적이 아니라 직접 역 선택 기반 알림 설정을 강화한다. 실제 FCM, 실시간 열차 위치 API, 백그라운드 위치 추적은 별도 기능으로 분리한다.

## 기능 목록

### 내릴 역 직접 선택

사용자는 검색 또는 추천 역 목록에서 내릴 역을 직접 선택한다.

**동작 방식**

- 홈 화면에서 역 검색을 연다.
- 사용자가 역명으로 검색하거나 추천 역을 선택한다.
- 선택한 역의 알림 설정 시트를 연다.
- 사용자는 push, vibration, voice 옵션을 설정한다.
- 저장하면 해당 역이 내 알림 목록에 추가된다.

**포함 범위**

- 기존 역 검색과 알림 설정 흐름을 기본 UX로 문서화한다.
- 위치 권한 요청 없이 역 선택만으로 알림을 설정할 수 있게 유지한다.
- 위치 기반 표현이 남아 있다면 직접 선택 기반 표현으로 정리한다.
- 제품 문구에서는 선택 대상을 `내릴 역`으로 부르고, `알림`은 방식과 시점 옵션으로 분리한다.

**제외 범위**

- 위치 권한 요청. 초기 기본 전략에서 제외한다.
- 현재 위치 기반 자동 역 감지. 지하철 환경에서 신뢰도가 낮다.
- 사용자가 실제 탑승한 열차 자동 식별.

### 수동 탑승 모드 확장 준비

위치 권한 없이도 이후 “몇 정거장 전 알림”으로 확장할 수 있도록 수동 탑승 모드의 입력 흐름을 고려한다.

**동작 방식**

- 사용자가 노선, 현재 역, 진행 방향, 내릴 역을 직접 선택하는 흐름을 후속 기능 후보로 둔다.
- 이번 기능에서는 기존 역 선택 알림 설정과 충돌하지 않도록 용어와 데이터 구조를 정리한다.
- 내릴 역 선택은 현재 알림 설정의 station 선택과 같은 모델을 재사용한다.

**포함 범위**

- 수동 탑승 모드가 후속 기능이라는 문서화.
- 기존 `SubwayAlert.station`이 내릴 역 역할을 할 수 있는지 검토.

**제외 범위**

- 정거장 진행 계산.
- 역 간 소요 시간 추정.
- 실시간 열차 위치 API 후보 매칭.

### 위치 권한 계획 제거

위치 권한 확인을 초기 기능 계획에서 제거한다.

**동작 방식**

- 위치 권한 요청 UI를 새로 만들지 않는다.
- iOS/Android 위치 권한 설정을 추가하지 않는다.
- 위치 권한이 없더라도 앱의 핵심 알림 설정 흐름은 동작한다.

**포함 범위**

- 이전 위치 권한 계획을 대체하는 기능 문서.
- 사용자에게 위치 권한 없이도 사용할 수 있다는 제품 방향.

**제외 범위**

- 기존 알림 권한 요청 제거. 알림 표시에는 여전히 필요하다.
- 도착 알림 엔진 삭제. 순수 로직은 향후 다른 입력과 연결될 수 있다.

## 입출력

**입력**

- 역 검색어. 문자열.
- 사용자가 선택한 내릴 역. `Station`.
- 알림 옵션. push, vibration, voice boolean.

**출력**

- 저장된 `SubwayAlert`.
- 내 알림 목록에 표시되는 선택 역.
- 위치 권한 없이 설정 가능한 알림 흐름.

## 제약 조건

- 위치 권한을 요청하지 않는다.
- 위치 좌표를 저장하거나 서버로 전송하지 않는다.
- 기존 역 검색, 알림 시트, 로컬 저장 흐름을 깨지 않는다.
- 알림 표시 자체에는 알림 권한이 필요할 수 있다.
- 수동 탑승 모드 전체 구현은 이번 범위가 아니다.

## 예외 케이스

- 검색 결과 없음 → 빈 상태를 보여준다.
- 이미 알림이 있는 역 선택 → 기존 설정을 수정한다.
- 알림 저장 실패 → 기존 상태를 유지하고 실패 안내를 보여준다.
- 알림 권한 거부 → 역 알림 설정은 저장하되 실제 알림 표시 제한을 안내한다.

## 채택 근거

**핵심 이유**

- 지하철 환경에서 위치 기반 자동 감지보다 사용자가 내릴 역을 직접 선택하는 방식이 더 안정적이다.

**보조 이유**

- 위치 권한 거부 사용자도 앱의 핵심 설정 흐름을 사용할 수 있다.
- 기존 앱 구조가 이미 역 검색과 알림 설정 중심으로 되어 있어 변경 비용이 낮다.
- 수동 탑승 모드와 실시간 열차 위치 연동을 후속 기능으로 확장하기 쉽다.

**기각된 대안**

- 위치 권한 기반 현재 위치 확인부터 구현한다. 지하 구간에서 신뢰도가 낮고 사용자 거부 가능성이 있다.
- 센서만으로 탑승 열차를 추정한다. 어느 역과 열차인지 확정하기 어렵다.
- 실시간 열차 위치 API만 사용한다. 사용자가 어떤 열차를 탔는지 자동으로 알 수 없다.

## 비기능 요건

**성능**

- 역 검색과 알림 설정 UI는 기존 반응성을 유지한다.

**보안**

- 위협 모델. 위치 정보를 수집하지 않는 대신 알림 설정 데이터만 로컬 또는 API에 저장한다.
- 위치 좌표, 위치 기록, 탑승 경로를 저장하지 않는다.

**확장성**

- 수동 탑승 모드는 별도 기능으로 `노선 → 현재 역 → 방향 → 내릴 역` 흐름을 추가할 수 있다.
- 실시간 열차 위치 API를 붙일 경우에도 사용자가 탄 열차 선택 또는 후보 확인 UI가 필요하다.

## 용어 정의

- **내릴 역.** 사용자가 최종적으로 내리고 싶은 목적 역이며 앱의 핵심 선택 대상이다.
- **알림 시점.** 내릴 역을 기준으로 언제 알려줄지 나타내는 옵션이다. 초기 흐름은 도착 알림을 기본으로 둔다.
- **알림 방식.** 푸시, 진동, 음성처럼 어떤 방식으로 알려줄지 나타내는 옵션이다.
- **수동 탑승 모드.** 사용자가 노선, 현재 역, 방향, 내릴 역을 직접 선택해 위치 권한 없이 알림 기준을 만드는 후속 흐름.
- **위치 권한 없는 흐름.** GPS나 기기 위치 접근 없이 역 선택과 알림 옵션만으로 동작하는 기본 사용 흐름.
